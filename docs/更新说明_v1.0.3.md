# 洛书匣 v1.0.3 更新说明

> 发布日期：2026-11-13
> 类型：缺陷修复与更新链路改造版（不改数据结构，可直接覆盖安装）

---

## 一、修复：酒馆扩展状态误判

**现象**：以前软件判断酒馆里配套扩展的安装与版本情况不准，已经装了新版仍提示「可升级」，或者实际没装却显示状态正常，让人不知道该不该点注入。

**现在的处理**：按酒馆扩展目录里实际存在的文件与版本号比对，装了就是装了、版本一致就不再提示，状态与酒馆里的实际情况一致。

---

## 二、修复：首次打开后路径设置被重置

**现象**：填好酒馆路径或资料库路径后，重新打开软件时路径又被还原成默认值或空值，需要每次重新选择。

**现在的处理**：已填写的路径会被保留，重启后仍然生效；仅在用户主动修改时才更新。

---

## 三、修复：预设卡片重复显示模型标签，且标签无法筛选与编辑

**现象**：同一个模型标签在预设卡片上重复出现多次；点这些标签既不能按它筛选，也不能编辑，形同装饰。

**现在的处理**：同一标签只显示一次，点击即可按该标签筛选；需要修改时可正常编辑。

---

## 四、修复：自定义标签与模型标签显示位置重合

**现象**：自己填的自定义标签和模型标签挤在同一个位置，两类标签混在一起，分不清哪个是模型带来的、哪个是自己加的。

**现在的处理**：自定义标签独立展示，与模型标签分开，便于区分与单独管理。

---

## 五、改进：从酒馆导入资源时按「名字·V版本号」命名

**现象**：以前从酒馆导入资源，卡片名称与酒馆里的版本信息脱节，同一资源的多个版本在书架上看不出差别。

**现在的处理**：导入后的名称统一为「名字·V版本号」，一眼能看出是哪个资源的哪个版本。

---

## 六、修复：书架右键菜单去掉重复的「打开详情」

**现象**：右键菜单里的「打开详情」与单击卡片打开详情重复，容易误点。

**现在的处理**：右键菜单不再提供「打开详情」，单击卡片即可查看详情。

---

## 七、修复：书架单选时不再弹出与右键重复的底部操作条

**现象**：在书架上单击选中一个资源，窗口下方就会弹出一条操作条，功能与右键菜单重复，还遮挡内容。

**现在的处理**：仅在选中 2 项及以上、需要进行批量操作时才出现该操作条；单选时直接使用右键菜单。

---

## 八、改进：更新检查不再依赖 GitHub API 的匿名配额

**现象**：以前检查更新直接调用 GitHub 的 API，同一网络环境下请求次数一多就会被匿名限流，检查更新频繁失败，只能等配额恢复。

**现在的处理**：

| 通道 | 作用 |
| --- | --- |
| `github.com` 跳转（302） | 主通道，直接取得最新 Release 的版本标签 |
| Release 的 atom 订阅 | 主通道取不到时自动改走该通道 |
| GitHub API | 前两条都不可用时的最后兜底 |

- 常规情况下不再消耗 API 匿名配额，限流导致的检查失败基本消除。
- 下载校验改为分级处理：能取到更新清单时按 SHA256 与文件大小严格校验；清单不可用时降级为按文件大小校验，不影响正常下载安装。
- 检查失败时的提示按原因区分（请求频繁被限流 / 网络不通 / 暂无发布版本），不再是笼统的一句「检查更新失败」。

## 九、升级建议

1. 直接覆盖安装本版即可，`%APPDATA%\TavernLib` 下的设置、黑名单、路径偏好与资料库索引不会丢失（本版不改数据结构）。
2. 若此前装过配套酒馆扩展，本版启动后会按实际版本给出准确状态，无需反复点「一键注入扩展」。
3. 本版未做代码签名，Windows SmartScreen 可能提示「未知发布者」，点「更多信息 → 仍要运行」即可。
