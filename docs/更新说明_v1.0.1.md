# 洛书匣 v1.0.1 更新说明

> 发布日期：2026-11-10
> 类型：缺陷修复版（无新增功能，数据结构未变，可直接覆盖安装）

---

## 一、修复：切换数据保存目录后封面全部变白

**现象**：在「设置 → 数据保存路径」里把库切换到新目录后，列表里的索引条目还在，但封面全部显示为空白。

**原因**：旧版本切换目录时只搬了 `library.json`（索引）和 `dc-token.bin`（凭据），图片仓库 `images`、`raw`、`thumbs` 仍留在原目录，新目录等于一个「有索引、没有图」的空壳，界面自然全是白图。原目录数据并未损坏。

**现在的处理**：切换目录改为整库搬迁。

| 环节 | 行为 |
| --- | --- |
| 搬迁内容 | 索引 `library.json`、凭据 `dc-token.bin`，以及 `images` / `raw` / `thumbs` 三个图片仓库（含子目录） |
| 执行顺序 | 先复制 → 再校验（源有目标缺即判定失败）→ 校验通过才写新路径指针 |
| 失败保护 | 复制中途出错或空间不足时直接中止，**旧目录继续可用**，不会出现两边都不完整 |
| 空间检查 | 复制前统计总字节并检查目标盘可用空间，需预留 5% + 8MB，不足则拒绝执行 |
| 已有数据 | 目标目录里若已有索引文件，先备份为 `.bak` 再覆盖；同名图片内容一致则跳过，不重复复制 |
| 进度反馈 | 搬迁过程中界面显示复制进度，不再无响应等待 |

> 说明：此前因该问题已经丢失的封面**不会自动回补**（旧图仍完整保留在原数据目录，默认 `%APPDATA%\tavern-lib\images`）。可把旧的 `images` / `raw` / `thumbs` 拷回当前数据目录后重启软件，或重新把路径切回旧目录。

## 二、修复：导入时帖子标题覆盖角色卡名

**现象**：同一批里同时导入「帖子链接」和「图片链接」时，角色卡自己的名字被帖子标题顶掉，需要逐个手改。

**原因**：导入流程把帖子标题无条件套用到本批所有行，没有区分这一行的名字到底来自角色卡本身、文件名，还是用户手动填写。

**现在的处理**：为每一行记录命名来源，按来源决定是否采用帖子标题。

| 命名来源 | 含义 | 是否被帖子标题覆盖 |
| --- | --- | --- |
| 角色卡自带名 | 从 PNG / JSON 卡片内读到的角色名 | 否，保留卡片原名 |
| 文件名 | 卡片内无名，取文件名兜底 | 是 |
| 用户手动 | 手动改过名字或填了别名 | 否 |

## 三、升级建议

1. 升级前建议先在软件内做一次「完整备份」（导出 ZIP）。
2. 直接覆盖安装本版即可，`%APPDATA%\TavernLib` 下的设置、黑名单、路径偏好不会丢失。
3. 未做代码签名，Windows SmartScreen 可能提示「未知发布者」，点「更多信息 → 仍要运行」即可。
